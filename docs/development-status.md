## Settled Product Architecture

One repository and Python distribution exposes two business surfaces:

| Surface | Entrypoint | Scope |
| --- | --- | --- |
| Function | `gemini-mcp-function` | Chat, Task, media, Research, status and results (six tools) |
| Account | `gemini-mcp-account` | Explicit conversation and Notebook management plus read-only Task metadata (six tools) |

`gemini-mcp-server` without `GEMINI_TOOLS` serves the function surface. Use `function-full` or `account-full` for the respective previous 17-tool catalog. The six-tool account surface runs on its own connection. Assist and compact remain compatible. In `account-full`, `gemini_cleanup` acts only on chats recorded as MCP-owned.

With the same JSON serializer on the modern MCP stdio path, the function tool list went from 33,315 to 14,909 bytes and the account tool list from 35,407 to 12,472 bytes. These figures measure tool discovery payloads.

Public tools use `gemini_` prefixes. `gemini_ask` remains distinct. Image, video, music and Deep Research start in the background by default. Function Ask with `notebook_ids` is background ordinary Chat (`execution_mode="chat"`), while `gemini_run_task` explicitly starts Task (`execution_mode="task"`). Both use 600-second phase timeouts by default. Operation metadata uses local SQLite with explicit opaque handles and primary `gemini_get_operation_status` / `gemini_get_operation_result` tools for restart and cross-client reads. Ordinary records have seven-day retention; an expired research record with a protected upstream chat remains recoverable until protection is released. A caller-supplied handle is needed to locate work if the initial response is lost. No prompts, chat/report text, Cookies, raw responses, or generated bytes are persisted in the ledger; verified answer files live separately with only their locators and verification metadata in SQLite.

A separate account-scoped SQLite cleanup queue survives restart and records verified deletion, leases, and retry state. Completed one-shot requests automatically attempt verified deletion before returning by default; failed verification stays pending for retry. Active sessions are preserved for subsequent turns and cleaned up after they end. Research stays protected until the worker saves and verifies the full nonempty local report or establishes a definitive failure. Unresolved background media, Research, Task and Notebook Chat are protected while their outcome is unknown. Task and Notebook Chat workers verify the exact completed reply and save and verify its full local answer Artifact before owned-chat cleanup, without waiting for the caller to request the result. Saved results remain readable by the original handle after restart. Notebook objects and sources are not temporary-chat cleanup targets. Cancellation remains unimplemented.

Account `gemini_notebooks` defaults to the Notebook source-picker view (`source="notebooklm"`); `source="gemini"` retains the same integrated product's project view and chat moves with fresh exact-target resolution. Default `gemini_tasks` provides read-only list/get/progress. `account-full` adds exact Task deletion with independent read-back. Task schedules remain separate from Chat scheduled actions. Bounded progress and explicit browser inputs are available. The background worker supports opt-in, one-time browser approval for MCP-owned Tasks. Exclusive handoff and Task pause/resume remain unavailable. See [Notebook, Chat and Task workflows](notebook-task-workflows.md).

The explicit-profile, assist and low-token servers remain compatibility surfaces.
