# Long Operations

Image, video, music and Deep Research start in the background by default. Function media, `gemini_run_task`, and function `gemini_ask` with `notebook_ids` always return a background handle. Notebook-backed Ask remains ordinary chat (`execution_mode="chat"`); Run Task explicitly uses `execution_mode="task"`. Save the returned `operation_id`; `background=false` selects the waiting path only on compatibility tools that expose it. A queued or running operation is not a completed Artifact or report.

Use primary `gemini_get_operation_status(operation_id=...)` and `gemini_get_operation_result(operation_id=...)`. Compact clients use `session(action="operation_status" | "operation_result", session_id=operation_id)`; assist clients use `gemini_research(action="status" | "result", operation_id=...)` and may omit `query`. All use the same operation database, so configure `GEMINI_OPERATION_DB_PATH` consistently across clients.

For recovery after a lost first response, provide a freshly generated `op_` plus 32 random lowercase hexadecimal characters as `operation_id`. Reuse only that handle to inspect the original work; do not resubmit the prompt or change its model or retention policy. If no upstream identity was observed, the handle can prevent a duplicate without guaranteeing recovery. Never reuse a pruned or expired handle.

Completion requires verified local media Artifacts, a ready nonempty Research document, or the exact completed Task/Notebook-chat answer. Task and Notebook-chat status reads metadata only and never regenerates. Their worker reads the original chat/request/candidate and verifies a full local answer Artifact. Task also saves and verifies the complete recognized native file-card inventory before automatic cleanup. A failed download or unknown shape preserves protection; a legacy answer without the inventory remains partial, rather than proving there were no files. The worker can finish after the submitting connection closes without a caller first requesting the result. Saved Artifacts remain available through the same operation handle after restart and are reverified locally. Operation SQLite contains locators and verification metadata, not answer text or generated bytes.

An unresolved operation stays protected from automatic remote-chat deletion. Request `retain_chat=true` only when the user wants retention. Notebook objects and sources are never chat-cleanup targets. Legacy Research recovery still depends on the original remote report if no saved local Artifact exists; a response interrupted after that chat's deletion may not be recoverable remotely. Status and result do not provide cancellation. Account `gemini_tasks(action="delete")` is explicit exact-ID deletion with read-back, not a cancellation capability.

Research workers save and verify the full ready nonempty Markdown report before cleanup, including after a submitter disconnects. Result previews are bounded to 4,000 characters; use the verified Artifact for the full text. Restarted reads rehash the original saved file without repeating research. For report derivatives after cleanup, pass `operation_id` to `gemini_list_research_report_actions` or `gemini_create_from_research_report`, omitting `chat_id`. This path reads only the verified local report. Missing or corrupt cache remains partial; a legacy deleted source without a saved report cannot be invented or regenerated by recovery.

`timeout_seconds=600` is the default for Task and Notebook-backed Chat phases. A timeout or lost connection does not authorize a second start, a different model, changed retention, or a mode switch. Preserve unknown states and the original handle.

For Task `input_required`, read the original card using `gemini_get_operation_result`. When the requested action is already authorized, call `gemini_run_task` with the original `operation_id`, returned `input_id`, selected `input_option_id` and exact selected `input_options` prompt. A card token dispatches once, preserves the original model/thinking/retention, and never grants user authorization by itself. An “always allow” option changes persistent permissions and needs that scope of authorization.

An App connection card instead returns `needs_attention` and `setup_required`. Connect or decline in the original native Task; text replies cannot complete OAuth. Metadata may indicate a previously observed setup card without revalidating it. Never treat that state as completion or fabricate a confirmation option.

Ordinary sessions have a separate lifetime. Function `gemini_send_message(session_id=..., recover_only=true)` without a message or images reads the previous unverified exact turn; it does not send a new prompt. An uncertain turn blocks new sends and remains protected. This recovery needs the original active server process, not the persistent operation database; compact/streaming schemas do not expose this argument.

Bounded Task progress, time schedules and explicit browser input are supported. Chat scheduled-action tools do not implement Task schedules. Associated schedules protect owned Task threads; independently verify schedule mutations and preserve timezone/fractional precision. Exclusive browser handoff, Task pause/resume, automatic permission approval and export are unavailable.

For `gemini_task_browser`, install `[browser-control]`. Input requires the returned exact reply IDs, prior frame hash and a unique action ID; the original Task must still be in state 3 or 5. Never replay an action ID or auto-approve login/permissions. A verified frame or input dispatch does not verify website effects or exclusive pause. See [tool_surface.md](tool_surface.md) for account-operation safety.
