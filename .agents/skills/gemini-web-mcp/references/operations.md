# Long Operations

Load this reference for Deep Research, video and music.

## Current Tools

- Focused `gemini_research(action="start")` starts once asynchronously; `action="status"`, `"result"`, `"cancel"` consume the returned operation_id. It is an opaque, restart-safe handle backed by local SQLite metadata.
- Focused `gemini_generate_music` / `gemini_generate_video` start once asynchronously. `gemini_get_operation_status`, `gemini_get_operation_result`, and `gemini_cancel_operation` accept that operation_id.
- Primary `gemini_deep_research` retains its synchronous compatibility default, also supports async starts and status/result/cancel by handle.
- Compact/primary synchronous media tools remain available. When they return queued/timeout, preserve known source identity and never repeat generation as recovery.

An opaque idempotency_key identifies a repeated start after response loss. Reuse the same key so the registered operation is returned without generating again. Never use prompts or response contents as an idempotency key.

## Persistent Recovery

The shared OperationService stores authentication-scoped identifiers, state, deadlines, output destinations, retention policy and artifact locators for seven days. It stores no prompts, chat/report contents, cookies, raw responses or generated bytes. Authentication scope is a private credential-lineage HMAC, not proof of Google account identity. Session timestamp refresh preserves its lineage; PSID rotation isolates it conservatively.

Status/result reads the known source or re-verifies local artifacts; it never resubmits the prompt or scans unrelated account history. Expired metadata returns OPERATION_EXPIRED. Research completion requires retrievable report evidence, not progress notices or changed text. local_cancelled_before_start verifies local cancellation before provider submission. For submitted work cancel_requested is best effort; cancellation_confirmed requires provider evidence.

## Media And Cleanup

Preserve every observed upstream identifier and artifact identity. timed_out is the local wait, not proof that Gemini stopped. Queued/remote/partial artifacts are not a completed media operation. Deadlines include generation, recovery reads, verification and save.

Automatic cleanup only owns the newly created source. All required output must be saved/verified, or the result must be definitively empty. Queued, uncertain, interrupted and incompletely saved work retains its source. Creation cleanup observations live in meta.details.cleanup: completed/already_completed records observed absence; pending/failed/retained does not. Artifact readiness remains independent of cleanup.

The focused account gemini_cleanup facade exposes status/run/cancel for registered durable jobs. Pending cleanup authority can be renewed until resolved; it is distinct from the seven-day operation lookup window. Explicit retain_chat/delete_after_seconds policy is persisted for recovery. A request to cancel a cleanup job cannot undo deletion already in flight.
