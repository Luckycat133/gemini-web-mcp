# Long Operations

Image, video, music and Deep Research start in the background by default. Function `task` and `ask` with `notebook_ids` always return a background handle. Notebook-backed Ask remains ordinary chat (`execution_mode="chat"`); `task` explicitly uses `execution_mode="task"`. Save the returned `operation_id`. A queued or running operation is not a completed Artifact or report.

Use `operation(operation_id=..., status_only=true)` for read-only status and `operation(operation_id=..., wait_seconds=...)` for verified results (on compatibility `--full` servers: `gemini_get_operation_status` / `gemini_get_operation_result`). Result recovery can trigger owned-chat cleanup. Compact clients use `session(action="operation_status" | "operation_result", session_id=operation_id)`. Assist clients use `gemini_research(action="status" | "result", operation_id=...)` and may omit `query`. Set `GEMINI_OPERATION_DB_PATH` to the same operation database across clients that recover the same operations.

For recovery after a lost first response, provide a freshly generated `op_` plus 32 random lowercase hexadecimal characters as `operation_id`. Reuse only that handle to inspect the original work; do not resubmit the prompt or change its model or retention policy. If no upstream identity was observed, the handle can prevent a duplicate without guaranteeing recovery. Never reuse a pruned or expired handle.

Completion requires verified local media Artifacts, a ready nonempty Research document, or the exact completed Task/Notebook-chat answer. Task and Notebook-chat status reads metadata only and never regenerates. Their worker reads the original chat/request/candidate and verifies a full local answer Artifact. Task also saves and verifies the complete recognized native file-card inventory before automatic cleanup. A failed download or unknown shape preserves protection; a legacy answer without the inventory remains partial, rather than proving there were no files. The worker can finish after the submitting connection closes without a caller first requesting the result. Saved Artifacts remain available through the same operation handle after restart and are reverified locally. Operation SQLite contains locators and verification metadata, not answer text or generated bytes.

An unresolved operation stays protected from automatic remote-chat deletion. Request `retain_chat=true` only when the user wants retention. Notebook objects and sources are outside chat cleanup. Legacy Research recovery still depends on the original remote report when a saved local Artifact is absent. Cancellation is not available. Exact-ID Task deletion with read-back is available in `account-full`.

Research workers save and verify the full ready nonempty Markdown report before cleanup, including after a submitter disconnects. Result previews are bounded to 4,000 characters. Use the verified Artifact for the full text. Restarted reads rehash the original saved file without repeating research. For report derivatives after cleanup, use the `function-full` tools `gemini_list_research_report_actions` or `gemini_create_from_research_report` with the original `operation_id`. This path reads only the verified local report. A missing or corrupt cache remains partial.

`timeout_seconds=600` is the default for Task and Notebook-backed Chat phases. A timeout or lost connection does not authorize a second start, a different model, changed retention, or a mode switch. Preserve unknown states and the original handle.

For Task `input_required`, read the original card using `gemini_get_operation_result`. When the requested action is already authorized, call `gemini_run_task` with the original `operation_id`, returned `input_id`, selected `input_option_id` and exact selected `input_options` prompt. A card token dispatches once, preserves the original model/thinking/retention, and never grants user authorization by itself. An “always allow” option changes persistent permissions and needs that scope of authorization. If the operator enabled `GEMINI_TASK_AUTO_APPROVE=true` in the service startup environment, the worker can submit one verified one-time browser grant for an MCP-owned Task. Website-created Tasks require the additional `GEMINI_TASK_WEB_APPROVALS` opt-in. Exact Google Tasks deletion approvals require a separate Task/title rule. [Approval configuration](https://github.com/Luckycat133/gemini-web-mcp/blob/codex/gemini-tools-polish-20261101/docs/task-preferences.md) Continue using the same operation handle. Status reads are read-only.

An App connection card instead returns `needs_attention` and `setup_required`. Connect or decline in the original native Task; text replies cannot complete OAuth. Metadata may indicate a previously observed setup card without revalidating it. Never treat that state as completion or fabricate a confirmation option.

Ordinary sessions use the original active server process. Call `gemini_ask(session_id=..., recover_only=true)` to read back the previous unverified turn without sending a prompt. An uncertain turn blocks new sends and remains protected. In `function-full`, use `gemini_send_message` with the same recovery arguments.

Bounded Task progress, time schedules and explicit browser input are supported. Chat scheduled-action tools do not implement Task schedules. Associated schedules protect owned Task threads; independently verify schedule mutations and preserve timezone/fractional precision. Exclusive browser handoff, Task pause/resume and export are unavailable.

For explicit `gemini_task_browser` actions, connect `account-full` and install `[browser-control]`. On repeat observations, pass the last `known_frame_sha256` to skip an unchanged image. Use `include_image=false` when you only need the verified PNG file. Input uses the exact reply IDs, `expected_frame_sha256` and a unique action ID. It requires Task state 3 or 5. Verify website effects independently. [Tool reference](tool_surface.md)

For a verified report or answer file without an inline preview, set `include_text=false` on an operation result read. Status, required input, and cleanup evidence still apply.
