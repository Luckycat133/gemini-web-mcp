# Long Operations and Source Cleanup

Read for Research, video/music starts, interruption or recovery.

## Start and Continue

Focused `gemini_research` returns immediately and uses
`action="status"|"result"|"cancel"` with `operation_id`. Focused video/music
returns a handle for `gemini_get_operation_status`,
`gemini_get_operation_result` and `gemini_cancel_operation`.

Primary Research defaults to waiting; `wait_for_completion=false` starts
asynchronously, with status/result/cancel on the same tool. Compact/primary
media may return queued/timeout output without durable handles; preserve its
known source identity.

For focused starts, an optional opaque `idempotency_key` supports response-loss
recovery. Preserve it before the call and reuse it only to retrieve that
registered request. New requests use new keys; the schema accepts 1–128 ASCII
letters, digits, `_` or `-`. Once a handle is returned, continue with that handle.

Preserve observed upstream IDs and artifact identities. Accepted/queued/running
are progress states; `timed_out` does not prove Gemini stopped. Creation's
deadline covers generation/save/verification. Research's start timeout bounds
plan/start, not the report. Recovery reads have separate bounded deadlines.

## Persistence and Cancellation

Authentication-scoped SQLite metadata/locators last seven days. Files remain
separate; the store contains no prompts, chat/report contents, credentials,
raw responses or generated bytes. Credential lineage is not Google account
identity: timestamp refresh preserves scope; PSID rotation isolates it.

Status/result reads known sources or saved artifacts without resubmitting.
Unknown, auth-mismatched or expired (`OPERATION_EXPIRED`) handles cannot
authorize account scans. Research needs a retrievable verified report;
progress/completion notices are insufficient.

`meta.verification_status=local_cancelled_before_start` proves no provider
submission. Submitted work remains `cancel_requested` unless
`cancellation_confirmed=true` has provider evidence. Cancellation does not
authorize deleting the recovery source.

## Source Cleanup

Automatic cleanup owns only this request's new source chat. It follows finished,
fully saved/verified output or a definitive empty response. Queued, interrupted,
remote-only, uncertain or partially saved work retains its source.
`retain_chat`/`delete_after_seconds` override the default policy.

Creation's `meta.details.cleanup` is independent of artifact readiness.
`completed`/`already_completed` records observed absence;
pending/failed/retained/cancelled does not. A verified file remains usable while
cleanup is unresolved; that failure does not authorize unrelated history reads.

Focused `gemini_cleanup` observes/runs/cancels registered jobs by known `job_id`.
Pending cleanup authority may renew beyond the operation lookup window.
Cancellation cannot undo deletion in flight. Preserve the output before
an authorized manual source deletion and use its recorded target ID.
