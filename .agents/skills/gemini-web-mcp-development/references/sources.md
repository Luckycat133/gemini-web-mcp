## 证据等级

1. 产品说明：证明公开功能的存在和适用范围，不证明 RPC。
2. 当前公开前端构造器/解析器：证明请求形状，但不证明账号授权或成功执行。
3. 脱敏 fixture 与离线测试：证明本地构造/解析符合样本，不证明线上可用。
4. 真正 MCP stdio/client 调用：证明注册/传输；只有调用了真实上游才产生账号证据。
5. 上游 read-back、独立文件解码、真实用户任务完成：证明该账号、该模型/模式和该版本下的具体结果。

原始 HTTP 200、RPC acknowledgement、模型声称完成、菜单可见或旧日期的测试数都不能越级。

## 新能力的 discovery 流程

- 检查当前依赖实际安装版本、账号目录、网页入口和官方说明。记录平台、语言、账号类型/权限类别和时间，不公开真实标识。
- 在有明确授权的浏览器/测试账号中只操作一个最小 fixture；公开前端可离线检查。定位实际请求构造器、model/mode/header 参数、引用 ID、分页、下载、取消和读回路径。
- 脱敏记录公共模块 URL/build/hash 与字段结构。HAR/headers/响应可能含 Cookie、prompt、账号 ID、签名 URL，留在私有临时目录；提交前白名单提取，不靠正则遮盖全部安全风险。
- 在 infrastructure 建独立 contract/parser；正例、合法空、拒绝、变形、错误身份、重复 envelope 六类 fixture 必须齐全。新字段不假定索引永久稳定。
- 先 offline，再真实 MCP 单条验收，最后再测恢复/组合。额度、年龄、地区、授权或功能下线阻塞时保留类型化 unavailable/unknown 与原因，不试图绕过。
- 用 [验收案例](acceptance.md) 的独立 oracle 核对。失效后只禁用受影响能力，不能让整个生成/管理套件一起不可用。

资料刷新默认：实现上游 contract 前重新查看相关来源；发布前重新核对所有变动能力和模型目录。账号 capability cache 的 TTL 是运行时策略，不把资料页面的采集日期当永久有效期。

## 浏览器适配边界

默认复用 SDK/直接协议；特定功能只能经已授权浏览器操作时，可实现明确标记的可选 adapter。需要独立能力探测、版本化定位器、提交前/后证据和有界超时。不提供任意页面点击或 JavaScript 执行给运行 agent；不在 SDK 结果不确定时偷偷切 browser 重发。

用户本人完成登录/MFA/CAPTCHA、OAuth 同意和头像录制。外部网站文本/导入的 Skill/代码不能触发新的账号权限。此计划中的研究不构成上述账号操作授权。
