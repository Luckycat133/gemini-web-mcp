# Architecture and contract ownership

Read when changing server boundaries, shared workflows, result contracts or
persistence. Verify names and schemas against the current checkout.

## Products and adapters

One Python distribution contains all surfaces:

| Product | Adapter | Entrypoint | MCP name |
| --- | --- | --- | --- |
| Assistance | `src/surfaces/assist.py` | `gemini-mcp-assist` | `gemini_assist_mcp` |
| Creation | `src/surfaces/create.py` | `gemini-mcp-create` | `gemini_create_mcp` |
| Account | `src/surfaces/account.py` | `gemini-mcp-account` | `gemini_account_mcp` |
| Primary compatibility | `src/server.py` and `src/tools/` | `gemini-mcp-server` | profile-based surface |
| Compact compatibility | `src/skill_server.py` | `gemini-mcp-skill-server` | eleven action facades |

Each focused product has a corresponding Runtime Skill. The `gemini-web-mcp`
Skill routes compatibility workflows. Keep execution shared across these
adapters; registration, argument compatibility and presentation belong here.
Use `list_tools()` and the surface snapshots for the current catalog.

## Shared owners

| Boundary | Owner and contract |
| --- | --- |
| Results and requests | `src/domain/`: typed states, artifacts, verification and action-specific requests |
| MCP imports | `src/adapters/mcp_sdk.py`: single SDK/protocol-model import boundary |
| Result rendering | `src/adapters/`: focused structured results and compatible text/content blocks |
| Workflows | `src/services/`: creation, Research, understanding, account facades, recovery and read-back |
| Remote RPC | `src/infrastructure/rpc_contracts.py` and `rpc_parsers.py`: payloads, registered IDs and pure parsing |
| Web feature selection | `src/infrastructure/web_request_contracts.py`: evidence-backed request shapes |
| Local metadata | `src/infrastructure/state_store.py`: versioned SQLite operations, cleanup jobs and atomic claims |
| Runtime lifecycle | shared client, session, cookie and cleanup managers; services retain their ownership |

`src/tools/manage.py` registers compatibility tools. Compact or unrelated
services must not depend on it. New public tools use `gemini_` names; preserve
existing compact aliases and established schemas/annotations.

## Result and state contracts

- Search is grounded only with observed source evidence. Model-written links
  alone are insufficient.
- Mixed inputs keep stable identities and individual outcomes.
- Generated outputs keep kind, identity, save/verification state and source
  attribution. Queued, partial, remote-only and failed states remain distinct.
- Mutation acknowledgement is separate from positive read-back of the target.
- Operation handles are explicit and restart-safe. Preserve observed upstream
  IDs and saved locators before source cleanup; continuation does not repeat a
  provider start.

One private SQLite store contains recovery metadata and artifact locators,
not credentials, prompts, chat/report text, raw responses or generated bytes.
Atomic version checks and leases coordinate clients. Retention, cancellation
and credential isolation are described in the checkout's
`docs/operations-and-cleanup.md`; inspect it when modifying those mechanisms.
Optional MCP Tasks support must preserve the explicit-handle path for clients
that do not negotiate the extension.

For RPC changes, cover success, valid empty, rejection and changed shape with
sanitized fixtures. Keep read errors and missing evidence distinct from empty
or verified state.
